# MYKabayan Tracker — Improvement Plan

*Prepared before making any code changes. Nothing below has been edited yet — this is for your approval.*

## What you have today

A **Next.js 14 + TypeScript + Tailwind + shadcn/ui** web app (~13,600 lines) generated by Zite from your 3 JSON exports. It talks **directly to your Google Sheet** through a service account (the `google-spreadsheet` library) rather than through your Apps Script web app. Sign-in is Google via NextAuth. Role-based tabs: **Admin, Dispatch, Accounts, Bossing, Liver, Purchasing, Invoicing, Settings**, plus a rate calculator, masterlist upload, invoice printing, client milestones/rewards, and brand theming.

Your **Apps Script stays useful** for what the app doesn't do: the AirLink webhook (`doPost`) that updates delivery status, and the smart customer-ID/duplicate merging. The two write to the same sheet, so they need to stay in sync (see below).

## Findings

### 1. The app does not build — 5 TypeScript errors (all small)

| # | File | Problem | Fix |
|---|------|---------|-----|
| 1 | `app/api/auth/[...nextauth]/route.ts` | Exports `authOptions` from a route file — Next 14 forbids non-route exports here. Fails `next build`. | Move `authOptions` into `lib/authOptions.ts`; route only exports `GET`/`POST`. |
| 2 | `components/SplitItemDialog.tsx` | Passes `phpRate` + silver rates to `splitItem()`, which doesn't accept them. | These are only needed client-side (`saveRatesForDate`). Drop them from the call. |
| 3 | `components/accounts/AddClientModal.tsx` | Same — passes rate fields to `createRecord()`. | Same: drop from the API call (still saved locally for rate-locking). |
| 4 | `components/purchasing/PurchasingTab.tsx` | Imports `GetRewardInventoryOutputType`, which isn't exported. | Export the type from `actions.ts` / `api.ts`. |
| 5 | `components/purchasing/PurchasingTab.tsx` | Calls `getRewardInventory({})` but the function takes no args. | Make the param optional. |

### 2. Live secrets are committed in `.env.local`

Your real **Google service-account private key**, **OAuth client secret**, and **NEXTAUTH_SECRET** are sitting in `.env.local` in the folder. Anyone with the folder can read/write your sheet and impersonate sign-in.

Fix: keep real values in an untracked `.env.local`, add/verify `.gitignore`, leave a safe `.env.example` with placeholders. **Recommend rotating** the exposed service-account key and OAuth secret in Google Cloud, since they've been shared.

### 3. Data-model correctness

- **Column mapping is correct.** The app's 39-column map (A–AM) lines up with your Apps Script's `dbRow[0..38]` and the masterlist sample. Good.
- **Masterlist import only reads the FIRST worksheet.** Your real masterlist file has one sheet per page/store (AR Universal, NERS, Sweet & Glam, J's) plus `DATA'S`. The app's parser (`masterlistImport.ts`) parses `SheetNames[0]` only — the other stores get dropped. Your Apps Script loops all sheets. **Fix: loop every sheet except `DATA'S`.**
- **Status vocabulary drift.** Import defaults to `"Pending"`, Apps Script uses `"Waiting for Details"` / `"Live"`, the UI uses others. Worth standardizing one list.
- **Header names must match exactly.** The app writes by column *header text*. If row 1 of your Database/Uploads/Roles tabs differs even slightly from the mapping (Uploads/Roles headers were partly guessed in the code comments), writes land in the wrong place or silently vanish. **Fix: verify against your live sheet once.**
- **The `DATA'S` sheet is your editable dropdown source** (Item Description, Currency, Category, Source, T.O.G, Liver, Pages). The app currently hardcodes these lists. Loading them from `DATA'S` would let you change options without touching code (feature — see §5).

### 4. UI/UX

Structure is genuinely good (role tabs, compact mode, brand theming, print invoices). Main issue is **readability**: type is extremely small (`9–11px` throughout) and dense, tuned for mobile but cramped and hard on desktop. Polish opportunities: readable type scale + spacing, better empty/loading/error states, a proper desktop layout, and search/filter/pagination for large record counts.

### 5. Feature-upgrade candidates (you choose which)

- **Dynamic dropdowns** loaded from the `DATA'S` sheet (categories, currencies, sources, TOG, livers, pages).
- **Multi-sheet masterlist import** (fixes §3; also treat it as a feature — preview + per-sheet summary before committing).
- **Bring AirLink status sync into the app** (or keep it as the Apps Script webhook) so dispatch status updates aren't split across two systems.
- **Performance:** cache records, pagination/virtualized lists, avoid full re-fetch on every edit.
- **Reporting/exports:** CSV/Excel export, sales & profit summaries per liver/page/date.
- **Reliability:** stronger optimistic-update rollback and error surfacing.
